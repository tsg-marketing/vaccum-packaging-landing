ЧАСТЬ 1. КРАТКИЙ ПРОМПТ (можно отправить только его)
================================================================================

Создай лендинг «Термоусадочное оборудование» по адресу /termousadka для
компании «Техно-Сиб» (поставка упаковочного оборудования).

Стек: React + TypeScript + Vite + Tailwind + shadcn/ui, иконки через
компонент <Icon name="..." /> (обёртка над lucide-react).

Шрифты: Montserrat (заголовки, 600/700/800) + Open Sans (текст, 400/500/600).

Цветовая схема (HSL, в src/index.css):
  --background: 0 0% 100%
  --foreground: 210 22% 15%
  --primary: 199 89% 48%      (голубой)
  --secondary: 210 22% 15%    (тёмно-синий, почти чёрный)
  --accent: 25 95% 53%        (оранжевый — все CTA-кнопки)
  --muted: 210 20% 96%
  --border: 210 20% 90%
  --radius: 0.5rem
В tailwind.config.ts: fontFamily.heading = Montserrat, fontFamily.sans = Open Sans.

Структура страницы сверху вниз (14 блоков):
1) Шапка (sticky) 2) Первый экран 3) Преимущества 4) Каталог 5) Видео
6) Применение 7) 7 признаков 8) Расходные материалы 9) Сопутствующие товары
10) Сервис и доставка 11) Квиз-подбор 12) О компании 13) FAQ
14) Форма заявки + Подвал

КЛЮЧЕВЫЕ УСЛОВИЯ ПЕРЕНОСА (подробности ниже):
  • Товары каталога берутся из YML-фида
    https://tehnosib.ru/upload/export_files/yml_tehnosib_4623.xml
    через функции импорта и выдачи товаров — см. раздел 2.4.
  • Видео вставляются ТЕГОМ-вставкой RuTube (embed), а не ссылкой —
    см. раздел 2.5.
  • Заявки уходят туда же, что и сейчас: POST /api/b24-send-lead.php —
    этот адрес НЕ менять.
  • Телефоны, email и счётчик Яндекс.Метрики брать с сайта нового
    лендинга, а не копировать со старого.

Все секции (кроме шапки и первого экрана) появляются с анимацией
fade-in-up при скролле — через хук useScrollAnimation на IntersectionObserver.

*** ОТКУДА БЕРУТСЯ ТОВАРЫ (ВАЖНО) ***

Первоисточник — YML-выгрузка (Яндекс.Маркет-фид) сайта Техносиб:
  https://tehnosib.ru/upload/export_files/yml_tehnosib_4623.xml

Цепочка работы с данными:
  1) Облачная функция импорта разбирает этот XML-фид и складывает товары
     (название, цена, картинки, характеристики, категория, видео) в базу данных.
  2) Облачная функция синхронизации обновляет базу из фида:
       POST https://functions.poehali.dev/c616cc5e-d577-4461-8ce7-6f6d5fbfd2f9
     Вызывается с фронта не чаще раза в 24 часа (отметка времени последнего
     запуска хранится в localStorage, ключ lastShrinkProductSync).
  3) Фронт получает готовые товары одним GET-запросом:
       https://functions.poehali.dev/2d5f9278-9fd7-4ee8-86c0-e8b7c096608c?categories=340,341,342,343,344,295,345
     Параметр categories — список ID категорий через запятую.
     Ответ: { "products": [ ... ] }

Структура товара в ответе:
  id              — внутренний числовой ID
  external_id     — ID товара из фида (используется для якорной ссылки
                    на товар вида #product-{external_id})
  name            — название
  price           — цена числом (0 = «Цена по запросу»)
  image_url       — ссылка на фото (может быть null)
  category_id     — ID категории
  specifications  — объект «характеристика: значение»
  description     — описание

В НОВОМ ПРОЕКТЕ: нужно поднять такие же функции импорта/выдачи товаров
(источник тот же — YML-фид выше) либо обращаться к уже существующим адресам
функций, указанным выше, если доступ к ним сохраняется.

Логика каталога:
  - Товары грузятся одним запросом (адрес выше), затем кэшируются
    в localStorage на 6 часов (ключи shrinkProductsCache_v4 и
    shrinkProductsCacheTimestamp_v4).
  - Поиск по названию товара (поле ввода над вкладками).
  - Сортировка: сначала товары с ценой (по возрастанию), затем «по запросу».
  - Карточка товара: фото (клик — лайтбокс на весь экран), название,
    краткие характеристики, цена (формат «123 456 руб») либо
    «Цена по запросу», кнопки «Узнать подробнее» и «Оставить заявку».
  - «Узнать подробнее» открывает карточку товара (ProductModal) с полным
    описанием, всеми фото и характеристиками.
  - «Оставить заявку» открывает модальное окно заявки, подставляя название
    товара в текст заявки.
  - Для каждой категории показываются только релевантные характеристики
    (например, для тоннелей — габариты тоннеля и скорость конвейера;
    для танков — ёмкость бака, температурный диапазон, мощность нагрева).
    Служебные поля скрываются: Бренд, Название бренда, Видео (ссылка),
    Видео, Картинки товара, а также поля с GUID-значениями.
  - На мобильных показываются первые 10 товаров + кнопка
    «Посмотреть все (N)».
  - Рядом с названием категории показывается количество товаров в ней.
  - Если активная категория пустая — автоматически переключается на первую
    непустую.
  - Поддержка прямых ссылок на товар: при заходе по адресу с якорем
    #product-{external_id} нужная категория выбирается автоматически
    и сразу открывается карточка этого товара.

*** КАК ДОБАВЛЯЮТСЯ ВИДЕО (ВАЖНО) ***

Видео размещаются на RuTube и вставляются НЕ ссылкой на страницу, а
ТЕГОМ-вставкой (embed). Из кода вставки RuTube берётся только идентификатор
видео (embedId) — длинная строка из 32 символов в адресе вида
  https://rutube.ru/play/embed/{embedId}/
Этот embedId передаётся в компонент как параметр — вся остальная разметка
(обложка, кнопка Play, плеер) строится автоматически.

Как получить embedId: на странице видео в RuTube нажать «Поделиться» →
«Встроить на сайт» (код для вставки, iframe) и скопировать из адреса
внутри тега то, что идёт после /play/embed/.

Компонент VideoCard: props { embedId: string; title?: string }
  - Обложка подтягивается автоматически по embedId:
    https://rutube.ru/api/video/{embedId}/thumbnail/?redirect=1
  - Поверх — затемнение и круглая оранжевая кнопка Play, при наведении
    картинка немного увеличивается.
  - По клику открывается модальное окно с плеером — тег iframe со ссылкой
    https://rutube.ru/play/embed/{embedId}/ подключается только в этот
    момент (ленивая загрузка: до клика видео не грузится и не тормозит
    страницу).
  - Чтобы добавить новое видео — достаточно вставить ещё одну строку
    <VideoCard embedId="..." title="..." />, ничего больше менять не нужно.

Два видео на странице:
  1. embedId: cea7e294490190af4e9d0dd10a018f75 | title: Термоусадочная упаковка
  2. embedId: 3aa838c3f9ac0f034175ba042f4d88c6 | title: Термоусадочный тоннель

Отдельно: видео может приходить и вместе с товаром из фида — в
характеристиках товара есть поле «Видео (ссылка)». В карточке товара оно
скрыто из списка характеристик и используется для показа видео товара.

Данные (7 карточек), структура { emoji, title, items[] }:

1. ✋ Вы до сих пор упаковываете вручную
   - Ручная обмотка — потеря 3–5 часов в смену
   - Неравномерная усадка, заломы
   - Торговые сети отказывают в приёмке
   - Решение: базовый полуавтомат окупается за 2–4 месяца

2. 📈 Текущий аппарат не справляется с объёмами
   - Заказов больше, аппарат на пределе
   - Очереди на упаковку тормозят отгрузку
   - Теряете клиентов из-за срывов сроков
   - Решение: переход на более производительную модель

3. 🔧 Частые поломки и простои
   - Аппарат ломается чаще раза в месяц
   - Запчасти ждать неделями
   - Стоимость ремонтов за год приближается к цене нового
   - Решение: замена на современный аппарат с гарантией

4. ❌ Высокий процент брака упаковки
   - Плёнка морщится, не усаживается
   - Прожоги и отверстия
   - Переупаковка 10–15% продукции
   - Решение: современные модели снижают брак до 1–2%

5. 🎞️ Оборудование не работает с нужным типом плёнки
   - Старый аппарат только на ПВХ, нужна ПОФ
   - Невозможность перейти на экологичные материалы
   - Клиенты требуют конкретный тип
   - Решение: новые аппараты работают с ПОФ, ПВХ, ПЭ

6. 🏪 Вы выходите в торговые сети или на маркетплейсы
   - Жёсткие требования к качеству
   - Wildberries, Ozon требуют герметичную упаковку
   - Ручная упаковка не проходит приёмку
   - Решение: термоусадочный аппарат обеспечивает стандарты ритейла

7. 🚀 Вы запускаете новый продукт или линейку
   - Новый продукт требует другого формата
   - Нужна групповая упаковка или мультипаки
   - Существующее оборудование не подходит по размерам
   - Решение: подбор аппарата точно под габариты

3.1. МАСКА ТЕЛЕФОНА
--------------------------------------------------------------------------------
Формат: +7 (999) 999-99-99. Функция форматирования:
  - убираем всё, кроме цифр;
  - если цифр больше 11 — не даём вводить дальше;
  - 1 цифра → «+7»
  - до 4 цифр → «+7 (999»
  - до 7 → «+7 (999) 999»
  - до 9 → «+7 (999) 999-99»
  - 11 → «+7 (999) 999-99-99»

--------------------------------------------------------------------------------
3.2. ОТПРАВКА ЗАЯВОК
--------------------------------------------------------------------------------
*** СИСТЕМА ОТПРАВКИ ЗАЯВОК ОСТАЁТСЯ ТАКОЙ ЖЕ — МЕНЯТЬ НЕ НУЖНО ***

Все формы (шапка/модалка, первый экран, квиз, форма внизу, кнопки
«Оставить заявку» в каталоге) отправляют POST-запрос с JSON на тот же
самый эндпоинт, что и сейчас:

  POST /api/b24-send-lead.php
  Content-Type: application/json

Этот адрес в новом лендинге оставить БЕЗ ИЗМЕНЕНИЙ — заявки должны уходить
туда же, в ту же CRM (Битрикс24). Никакие облачные функции для приёма заявок
создавать не нужно.

Тело запроса (ключи):
  name              — имя
  phone             — телефон
  email             — email
  comment           — текст заявки (см. ниже)
  message           — то же, что comment (дубль для совместимости)
  url               — адрес страницы-источника
  UF_CRM_1775454267 — строка 'ДА' (служебное поле CRM)
  yaClientId        — ClientID Яндекс.Метрики (может быть пустым)
  utm_source, utm_medium, utm_campaign, utm_term, utm_content — из cookie

Текст comment собирается построчно и включает:
  Интересует товар - {название}      (если заявка из карточки товара)
  Страница: Термоусадочное оборудование — https://vacuum.t-sib.ru/termousadka/
  {комментарий пользователя}          (если есть)
  ClientID: {значение}                (если получен)

Запрос отправляется «в фон» — ошибка сети не показывается пользователю
(.catch(() => {})), уведомление об успехе показывается сразу.

3.5. АНИМАЦИЯ ПРИ СКРОЛЛЕ
--------------------------------------------------------------------------------
Хук useScrollAnimation на IntersectionObserver: возвращает ref и флаг
видимости. Секция получает класс анимации (fade-in-up) только когда
попадает в область просмотра. Для каждой секции — свой отдельный вызов хука.
Классы анимаций (animate-fade-in-up, animate-fade-in, animate-scale-in)
описываются в tailwind.config.ts через keyframes.
