ЧАСТЬ 1. КРАТКИЙ ПРОМПТ (можно отправить только его)
================================================================================

Создай лендинг «Запайщики лотков (трейсилеры)» по адресу /traysealers для
компании «Техно-Сиб» (поставка упаковочного оборудования).

Стек: React + TypeScript + Vite + Tailwind + shadcn/ui, иконки через
компонент <Icon name="..." /> (обёртка над lucide-react).

Шрифты: Montserrat (заголовки, 600/700/800) + Open Sans (текст, 400/500/600).

Цветовая схема (HSL, в src/index.css):
  --background: 0 0% 100%
  --foreground: 210 22% 15%
  --primary: 199 89% 48%      (голубой)
  --secondary: 210 22% 15%    (тёмно-синий, почти чёрный)
  --accent: 25 95% 53%        (оранжевый — все CTA-кнопки)
  --muted: 210 20% 96%
  --border: 210 20% 90%
  --radius: 0.5rem
В tailwind.config.ts: fontFamily.heading = Montserrat, fontFamily.sans = Open Sans.

Структура страницы сверху вниз (12 блоков):
1) Шапка (sticky) 2) Первый экран 3) Преимущества 4) Каталог 5) Применение
6) 7 признаков 7) Демо-зал 8) Гарантия и доставка 9) Сервис и доставка
10) Квиз-подбор 11) О компании 12) Форма заявки + Подвал

Все секции (кроме шапки и первого экрана) появляются с анимацией
fade-in-up при скролле — через хук useScrollAnimation на IntersectionObserver.

КЛЮЧЕВЫЕ УСЛОВИЯ ПЕРЕНОСА (подробности ниже):
  • Товары каталога берутся из XML-фида каталога t-sib.ru:
    https://t-sib.ru/upload/catalog.xml
    через функции синхронизации и выдачи товаров — см. раздел 2.4.
  • Видео товара приходит из тега <param name="Видео (ссылка)">
    в том же XML-фиде — см. раздел 2.5.
  • Заявки уходят туда же, что и сейчас: POST /api/b24-send-lead.php —
    этот адрес НЕ менять.
  • Телефоны, email, адреса офисов и счётчик Яндекс.Метрики брать с сайта
    нового лендинга, а не копировать со старого.

*** ОТКУДА БЕРУТСЯ ТОВАРЫ (ВАЖНО) ***

Первоисточник — XML-выгрузка каталога сайта t-sib.ru:

  ОСНОВНОЙ ФИД (из него берутся все запайщики лотков):
    https://t-sib.ru/upload/catalog.xml
    Категории запайщиков в этом фиде: 307, 308, 309, 310, 498, 499

Формат фида — YML (стандарт Яндекс.Маркета): товары лежат в тегах <offer>,
у каждого есть <categoryId>, <name>, <price>, несколько <picture>
и набор характеристик в тегах <param name="...">.

Цепочка работы с данными:
  1) Облачная функция синхронизации скачивает XML, разбирает теги <offer>,
     отбирает товары нужных категорий и складывает их в базу данных
     (название, цена, все картинки, характеристики, описание).
       POST https://functions.poehali.dev/c616cc5e-d577-4461-8ce7-6f6d5fbfd2f9
     Вызывается с фронта не чаще раза в 24 часа (отметка времени последнего
     запуска хранится в localStorage).
  2) Фронт получает готовые товары одним GET-запросом:
       https://functions.poehali.dev/2d5f9278-9fd7-4ee8-86c0-e8b7c096608c?categories=307,308,309,310,498,499
     Параметр categories — список ID категорий через запятую.
     Ответ: { "products": [ ... ] }

Структура товара в ответе:
  id              — внутренний числовой ID
  external_id     — ID товара из фида (атрибут id тега <offer>);
                    используется для прямой ссылки вида #product-{external_id}
  name            — название
  price           — цена числом (0 = «Цена по запросу»)
  image_url       — главное фото (первый тег <picture>)
  images          — массив всех фото товара
  category_id     — ID категории (тег <categoryId>)
  specifications  — объект «характеристика: значение», собранный из тегов
                    <param name="...">; если у тега есть атрибут unit,
                    единица измерения добавляется к значению
  description     — описание

В НОВОМ ПРОЕКТЕ: нужно поднять такую же функцию синхронизации и функцию
выдачи товаров (источник тот же — https://t-sib.ru/upload/catalog.xml),
либо обращаться к уже существующим адресам функций, указанным выше,
если доступ к ним сохраняется.

Логика каталога:
  - Товары грузятся одним запросом (адрес выше), затем кэшируются
    в localStorage (примерно на 6 часов). При недоступности сети
    используется устаревший кэш, чтобы каталог не оставался пустым.
  - Вкладка «Все запайщики» показывает товары всех категорий сразу.
  - Пустые категории (0 товаров) в списке вкладок не показываются.
  - Рядом с названием категории показывается количество товаров в ней.
  - Поиск по названию товара (поле ввода над вкладками).
  - Сортировка: сначала товары с ценой (по возрастанию), затем «по запросу».
  - Карточка товара: галерея фото с перелистыванием (стрелки влево/вправо),
    название, краткие характеристики, цена (формат «123 456 руб») либо
    «Цена по запросу», кнопки «Узнать подробнее» и «Оставить заявку».
  - Клик по фото открывает лайтбокс на весь экран.
  - «Узнать подробнее» открывает карточку товара с полным описанием,
    всеми фото и характеристиками.
  - «Оставить заявку» открывает модальное окно заявки, подставляя название
    товара в текст заявки.
  - Служебные характеристики скрываются из таблицы: «Бренд»,
    «Название бренда», «Видео (ссылка)», «Видео», «Картинки товара»,
    а также поля с GUID-значениями.
  - На мобильных показывается ограниченное число товаров + кнопка
    «Посмотреть все».
  - Поддержка прямых ссылок на товар: при заходе по адресу с якорем
    #product-{external_id} нужная категория выбирается автоматически
    и сразу открывается карточка этого товара.

2.5. ВИДЕО ТОВАРА — ИЗ ТЕГА В XML-ФИДЕ
--------------------------------------------------------------------------------
*** ВАЖНО ***
Отдельной секции с роликами на этой странице нет. Видео привязано к товарам
и приходит из каталога вместе с остальными данными: в фиде
https://t-sib.ru/upload/catalog.xml внутри тега <offer> есть тег
  <param name="Видео (ссылка)">ссылка на видео</param>
(встречается также вариант с именем «Видео»).

При синхронизации это значение попадает в характеристики товара
(specifications) вместе со всеми остальными параметрами. На фронте поля
«Видео (ссылка)» и «Видео» скрыты из списка характеристик — они не
показываются как обычная строка таблицы, а используются для вывода
видео товара.

Если понадобится добавить секцию с роликами (как на странице термоусадки):
видео размещаются на RuTube и вставляются тег-вставкой (embed). Из адреса
вида https://rutube.ru/play/embed/{embedId}/ берётся только идентификатор
embedId, обложка подтягивается автоматически по адресу
https://rutube.ru/api/video/{embedId}/thumbnail/?redirect=1, а сам плеер
(iframe) подключается только по клику — до этого видео не грузится.

2.7. «7 ПРИЗНАКОВ» (id="signs", фон bg-muted/30)
--------------------------------------------------------------------------------
Заголовок H2: «7 признаков, что вам нужен новый трейсилер»
Подзаголовок: «Узнали хотя бы 2 пункта? Пора действовать.»
Сетка: sm:2, lg:3, xl:4. В карточке — эмодзи, номер (1–7), заголовок и
список пунктов. Последний пункт каждого списка начинается со слова
«Решение:» и выделяется (цветом accent/primary и жирным).

Данные (7 карточек), структура { emoji, title, items[] }:

1. 🔧 Вы до сих пор упаковываете вручную или используете бытовой вакууматор
   - Ручная запайка — потеря 3–5 часов в смену
   - Неровные швы, негерметичные лотки
   - Торговые сети возвращают партии из-за нарушения герметичности
   - Срок годности продукта сокращается
   - Решение: базовый полуавтоматический трейсилер окупается за 2–3 месяца

2. 📈 Текущий аппарат не справляется с объёмами
   - Заказов больше, аппарат запаивает по 1–2 лотка за цикл
   - Очереди на линии упаковки тормозят отгрузку
   - Теряете клиентов из-за срывов сроков поставки
   - Решение: переход на более производительную модель (до 15–20 циклов/мин)

3. 🔩 Частые поломки и простои
   - Матрица изнашивается, пресс не обеспечивает герметичность
   - Запасные части приходится ждать неделями
   - Стоимость ремонтов за год приближается к цене нового аппарата
   - Решение: замена на современный трейсилер с гарантией и сервисной поддержкой

4. ❌ Высокий процент брака упаковки
   - Плёнка не приваривается по всему контуру
   - Лотки деформируются при запайке
   - Возвраты 10–15% продукции из-за разгерметизации
   - Решение: современные модели с точным контролем температуры и давления
     снижают брак до 1–2%

5. 🎞️ Нужна модифицированная газовая среда (MAP)
   - Продукт требует увеличения срока годности без консервантов
   - Текущий аппарат не поддерживает газацию (MAP/GAP)
   - Клиенты (HoReCa, сети) требуют упаковку в МГС
   - Решение: трейсилеры с функцией MAP продлевают срок годности в 2–5 раз

6. 🏪 Вы выходите в торговые сети или на маркетплейсы
   - Жёсткие требования к внешнему виду и герметичности упаковки
   - Wildberries, Ozon, X5 требуют стандартизированный лоток с запайкой
   - Ручная упаковка не проходит приёмку ритейлера
   - Решение: трейсилер обеспечивает стабильное качество, соответствующее
     стандартам ритейла

7. 🚀 Вы запускаете новый продукт или линейку
   - Новый продукт требует другого формата лотка (круглый, овальный, глубокий)
   - Нужна скин-упаковка или вакуумная запайка
   - Существующее оборудование не подходит по размерам/функциям

--------------------------------------------------------------------------------
3.1. МАСКА ТЕЛЕФОНА
--------------------------------------------------------------------------------
Формат: +7 (999) 999-99-99. Функция форматирования:
  - убираем всё, кроме цифр;
  - если цифр больше 11 — не даём вводить дальше;
  - 1 цифра → «+7»
  - до 4 цифр → «+7 (999»
  - до 7 → «+7 (999) 999»
  - до 9 → «+7 (999) 999-99»
  - 11 → «+7 (999) 999-99-99»

--------------------------------------------------------------------------------
3.2. ОТПРАВКА ЗАЯВОК
--------------------------------------------------------------------------------
*** СИСТЕМА ОТПРАВКИ ЗАЯВОК ОСТАЁТСЯ ТАКОЙ ЖЕ — МЕНЯТЬ НЕ НУЖНО ***

Все формы (шапка/модалка, первый экран, квиз, форма внизу, кнопки
«Оставить заявку» в каталоге, кнопки «Записаться» в демо-зале) отправляют
POST-запрос с JSON на тот же самый эндпоинт, что и сейчас:

  POST /api/b24-send-lead.php
  Content-Type: application/json

Этот адрес в новом лендинге оставить БЕЗ ИЗМЕНЕНИЙ — заявки должны уходить
туда же, в ту же CRM (Битрикс24). Никакие облачные функции для приёма заявок
создавать не нужно.

Тело запроса (ключи):
  name              — имя
  phone             — телефон
  email             — email
  company           — компания (если поле есть в форме)
  comment           — текст заявки (см. ниже)
  message           — то же, что comment (дубль для совместимости)
  url               — адрес страницы-источника
  productType       — тип продукции (или '-')
  modeltype         — модель/тип оборудования (или '-')
  UF_CRM_1775454267 — строка 'ДА' (служебное поле CRM)
  yaClientId        — ClientID Яндекс.Метрики (может быть пустым)
  utm_source, utm_medium, utm_campaign, utm_term, utm_content — из cookie

Текст comment собирается построчно и включает:
  Интересует товар - {название}      (если заявка из карточки товара)
  Страница: Запайщики лотков — https://vacuum.t-sib.ru/traysealers/
  {комментарий пользователя}          (если есть)
  ClientID: {значение}                (если получен)

Запрос отправляется «в фон» — ошибка сети не показывается пользователю
(.catch(() => {})), уведомление об успехе показывается сразу.

описываются в tailwind.config.ts через keyframes.
